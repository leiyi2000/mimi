# Rich Reply Rendering

仅在图片比普通聊天文本更易读时调用 `render_rich_reply`，例如：

- 回答包含多个主题分段、较长步骤清单或参数对比表。
- 项目总结、调研结论或方案说明预计包含至少三个并列主题，正文会形成信息密集的长消息。
- 用户明确要求海报、长图、信息图或图片版总结。
- 内容需要保持稳定的表格列和视觉层级。

简单问答和未达到自动渲染阈值的短回复继续使用文本，不要为了装饰而渲染。普通文字、代码、命令、
错误信息统一按正文长度判断，不因内容类型跳过渲染。

渲染图片必须包含完整答案：

- `title` 使用直接描述主题的短标题。
- `subtitle` 只放一句上下文或结论摘要。
- 每个 `sections` 元素聚焦一个主题；优先使用 `body` 或 `bullets`，只有真实对比数据才用
  `table`。
- 表格最多 6 列，单元格保持简短。不要把段落强行塞入表格。
- 不传 HTML、Markdown、脚本、图片 URL 或样式；工具会统一转义和排版。

工具返回 `RICH_REPLY_RENDERED` 后，不要在聊天正文中重复图片内容，也不要补“已整理成
图片”等状态说明。若答案含有用户需要复制的少量命令，只发送这些可复制内容。工具
失败时改用普通文本回答，并明确说明图片渲染失败。
