# Yasuo

Yasuo 归档 QQ 群消息和图片，记录群撤回事件，并提供同群撤回消息海报。

## 群聊命令

| 命令 | 说明 |
| --- | --- |
| `群撤回` | 生成当前群最近 5 条撤回消息海报 |
| `群撤回 <1-10>` | 生成指定数量的最近撤回消息海报 |
| `原始消息` | 单独发送最近一条撤回消息 |
| `原始消息 <序号>` | 单独发送从新到旧的第 N 条撤回消息，序号不设上限 |

海报展示群友头像、昵称、原消息发送时间、已归档文本和图片，以及撤回时间。撤回事件存在但
原消息、文本或图片没有归档时，该记录仍会展示，并明确标记“原消息未存储”“图片未存储”
或“图片不可用”。

查询只作用于命令所在群，不支持指定成员、跨群查询或 HTTP 撤回记录查询。每条记录最多
展示 4 张图片；更多图片会显示剩余数量。

单独发送原消息时，文本、QQ 表情和全部已归档图片会按原顺序作为 QQ 原生消息段发送。
语音、视频、文件、卡片和合并转发只发送类型占位；无法重建的表情以及未归档或损坏的
图片会显示明确提示。消息末尾会标注原发送者和发送时间。

## HTTP API

现有 `POST /` 接口继续提供群消息分页查询，不返回撤回事件。请求体是
`GroupMessage.filter()` 的过滤条件，查询参数为 `page` 和 `page_size`。

Niu 只调用默认绑定在 `127.0.0.1:6273` 的专用只读接口：

- `POST /v1/agent/members/resolve`
- `POST /v1/agent/messages/search`

专用接口显式限制当前群、字段、游标、页大小和文本总量，不返回图片 Base64 或原始媒体。

## 数据

- SQLite：`data/yasuo.db`
- 群图片：`data/images/<group_id>/<message_id>/`
- 表：`group_messages`、`group_recalls`

`data/` 是运行数据目录，不应提交到 Git。
