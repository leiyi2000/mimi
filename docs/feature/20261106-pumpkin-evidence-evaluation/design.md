# Pumpkin 纠正验收证据与行为回归

## 范围

本轮先补纠正任务的内容核验，以及可重复运行的短链路行为评测。不增加规划或反思 Agent，
不改变模型配置，不将具体失败案例写入生产关键词或人格提示词。用户已确认实施。

## 纠正验收

`TaskCommandService.complete_task` 保留条件 ID、作用域、revision 和 Artifact 门禁，
随后调用独立的 `TaskVerificationService`。该服务用当前任务模型进行一次核验请求，
输入只包含条件、当前候选文件的实际内容和 Runtime 生成的证据引用，不携带执行器历史
或其“已经满足”的声明。图片使用受限预览，UTF-8 文本使用有界正文；不可读取或不支持的
格式保持不确定，不能仅凭文件存在或格式可解码确认语义条件。
当前核验最多读取 8 个候选文件；正文每文件最多 16000 字符、合计 48000 字符，
超限不截断后宣称通过。图片核验最多读取 2400 万像素，预览长边不超过 1600；
只能核验首帧预览可见信息，不能由此证明动画、来源真伪或生成策略。无文件时以实际
交付的结果正文为候选，不能把“已完成”这类声明当成外部操作成功的证据。

核验输出使用 passed、failed、unknown，必须覆盖全部稳定条件 ID，并关联输入中存在的
证据。只有全部 passed 才允许被纠正结果完成或交付；缺证据、模型失败或格式非法都明确
拒绝，保留候选文件。模型核验属于概率性检查，不宣称消除语义误判。

记录复用既有 idempotency 和 TaskEvent evidence，不新增数据库表。核验缓存绑定
task、scope、revision、条件和候选内容摘要；文件变化使缓存失效。提交完成前再次核对
revision 和候选内容，不能沿用旧文件核验结果。原任务没有纠正条件时保留原有完成契约，
通用任务的全面证据验收不属于本轮。

## 短链路评测

新增插件内独立评测入口，以合成 NapCat 消息和实际出站结果为边界。案例使用配置注入
的助手名称，覆盖无关话题静默、引用追问、领域切换、闲聊长度、现成资源请求和失败回执。
评分规则与输入分离，不能把期望交给被测助手。

离线模式仅验证运行与评分协议，明确标记为 contract replay；真实模型模式需要显式
开启，在隔离数据目录和 Fake NapCat 中运行插件进程，不连接真实 QQ，不读取内部
数据库、提示词或工具调用评分。语义评审只读取可见输入、出站文本和实际媒体，输出
通过、失败或不可判定；没有真实模型运行的数据不能记为能力提升。

这些是针对已知问题的短回归，与
`docs/feature/20261021-pumpkin-capability-evaluation/design.md` 的开放式 50 回合群聊
评测分开报告，不能替代正式群聊能力评测。

## 验证与兼容

先建立“只提交条件 ID”“证据缺失”“核验失败”“证据伪造”“候选文件变化”的回归，
再接入核验服务。执行 Pumpkin 全量测试和相邻 Help 测试，补离线评测 smoke。默认测试
不依赖模型网络、QQ 或生产数据；不部署或重启服务。命令清单无聊天命令变化，README、
架构和特性索引同步说明新边界。

## 入口与调用链

`plugins/pumpkin/runtime/app.py` 将 `provider_task`、`PumpkinStore` 和 `TaskService`
注入 `TaskVerificationService`，再注入 `TaskCommandService`。`complete_task` 先执行
既有 Artifact 与条件声明门禁，再读取候选实际内容，核对登记摘要，执行一次最长 45 秒
的核验请求。核验报告只能包含稳定条件 ID、三态结果和已存在的证据 ID；不能携带任意
附加字段。成功报告缓存复用既有 idempotency，进度事件只保存候选摘要证据。
缓存不是由执行器提交的 TaskEvent 读取，伪造审计事件不能绕过门禁。
完成锁内重建候选指纹，条件、revision 或文件变化都拒绝提交；原子完成事务与 Outbox
交付沿用既有路径。核验失败不消耗旧的来源重复违规次数，也不删除候选结果。

`plugins/pumpkin/evaluate.py` 的 `EvaluationRunner` 为每个短案例创建独立临时数据目录、
Fake NapCat 和 `main.py` 子进程。`FixtureModelServer` 不读取或记录模型请求正文，
离线模式使用固定脚本回复验证协议；真实模式仅继承模型配置，独立 `BehaviorJudge`
读取可见输入、出站结果和受限图片预览。任务型案例持续观察到时间窗口结束，
提交确认不能充当完成结果。无法读取的媒体和评审失败都返回 unknown；模型故障回执案例
单独标记故障注入。JSON 报告只保存状态、计数、媒体摘要和评审结论，以原子替换写入
默认 Git 忽略的 `plugins/pumpkin/tests/output/`。

本实现未执行真实模型评测，离线通过只证明回放和评分协议可运行。生产搜索、浏览器、
音频和代码服务凭据不进入测试进程；短案例中的资源任务主要验证无可用工具时的如实反馈。
命令和真实模型参数见插件 README。

引用追问回放发现 `reply_and_complete` 的固定幂等值曾在同一 scope 的不同 Turn 间
复用发送结果，使模型生成了新回复却没有第二次出站。当前幂等值绑定 `context.run_id`，
同 Turn 的重试保持幂等，不同 Turn 独立发送；既有旧键不会被新回合读取。
回归同时验证正常跨回合发送与已发送回复不重复，不为具体追问增加语义分支。
