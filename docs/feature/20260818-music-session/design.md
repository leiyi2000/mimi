## 2. 代码实现流程

### 2.1 启动与状态装配

`plugins/music/main.py` 先按需加载 `.env.dev`，再由 `Config.from_env()` 一次性读取
NapCat、网易云 API、签名服务、Cookie 文件和管理员列表。`main()` 创建唯一的
`NeteaseAuth`、`MusicService` 与 `LoginSession`，随后连接 NapCat。

`NeteaseAuth.__init__()` 优先读取运行时 Cookie 文件；仅在文件不存在时使用环境变量
初始化并持久化。这样聊天命令写入的新 Cookie 不会在重启后被旧环境变量覆盖。

### 2.2 点歌链路

入口仅处理单文本消息。`点歌` 的剩余参数由 `parse_query()` 按第一个 `-` 拆成歌曲名和
歌手名，然后进入：

```text
点歌 <歌曲名>[-歌手名]
  -> MusicService._search()
  -> 选择首项或歌手精确匹配项
  -> asyncio.gather(_play_url(), _detail())
  -> _play_url() 按需携带共享 Cookie
  -> _sign() 请求音乐卡片签名
  -> NapCat Json 消息
```

播放地址和歌曲详情并发获取。签名结果必须是包含 `app` 的字典；网络或 HTTP 错误最多
重试三次，每次间隔一秒。`MusicError` 只承载可以直接展示给用户的错误文本。

### 2.3 共享登录链路

`网易云登录` 仅管理员可用。无参数时 `handle_login()` 先占用 `LoginSession.active`，
避免多个扫码轮询并发，再依次创建 key、生成二维码并每三秒查询状态：

```text
801 等待 -> 802 已扫码 -> 803 授权成功并保存 Cookie
                         -> 800 二维码过期并结束
```

重复登录请求会复用当前二维码。带参数时 `handle_set_cookie()` 接受完整 Cookie 或裸
`MUSIC_U`，先调用登录状态接口校验，再持久化。`网易云信息` 读取共享账号资料；
`网易云登出` 先尝试通知上游，再无条件清除本地 Cookie。

### 2.4 消息循环

耗时的登录、登出和账户信息操作由 `asyncio.create_task()` 启动，不阻塞后续 NapCat
事件；普通点歌在当前事件中等待完成。连接层捕获异常、记录堆栈并等待五秒重连。

## 3. 设计取舍

签名提供方曾两次变化，但修改集中在配置和服务层，没有扩散到消息循环。共享登录与搜索
服务分开，使 Cookie 失效、搜索失败和签名失败可以独立定位。

## 4. 状态与边界

- `网易云登录` 与 `网易云登出` 仅允许 `ADMINS`。
- Cookie 可由环境变量初始化，也可保存到数据文件。
- 搜歌经 `ncm-api`，卡片签名是另一条外部链路。
- 日志和文档不能出现 `MUSIC_U`、完整 Cookie 或签名密钥。

## 5. 失败行为

- 搜索无结果或会员歌曲没有播放地址：转换为明确的用户提示。
- 签名响应无效、非 JSON 或网络失败：有限重试后统一提示服务不可用。
- 二维码创建失败：结束当前 session，允许下一次命令重试。
- 二维码状态查询暂时失败：保留轮询；过期或成功后在 `finally` 中清空 session。
- 上游登出失败：记录警告，但仍删除本地 Cookie，避免继续携带失效状态。

## 6. 验证

修改时分别验证搜索、签名错误、二维码并发、过期、Cookie 校验、权限和断线重连。
